# 2.5. Matriz de Priorização MoSCoW

A matriz MoSCoW foi utilizada para priorizar os requisitos funcionais e não funcionais do projeto **Agente Inteligente para Análise da Gestão Financeira Municipal**, considerando a importância de cada requisito para a primeira iteração e para a construção do MVP.

## Must Have — Indispensáveis para o MVP

**RF01, RF02, RF03, RF04, RF05, RF06, RF08, RNF01, RNF02, RNF05**

- **RF01 — Controle de perfil de acesso:** essencial para restringir funcionalidades de acordo com o perfil do usuário.
- **RF02 — Anonimização de identificadores:** indispensável para evitar exposição desnecessária de dados pessoais.
- **RF03 — Tratamento de valores ausentes:** necessário para garantir uma base de dados adequada às análises.
- **RF04 — Tratamento de duplicidades:** necessário para reduzir inconsistências nos dados utilizados pelo sistema.
- **RF05 — Consulta de dados tributários:** funcionalidade central para acesso e análise das informações disponíveis.
- **RF06 — Definição da variável-alvo:** necessária para orientar corretamente a predição de inadimplência.
- **RF08 — Cálculo do score de recuperabilidade:** requisito central para apoiar a análise da recuperabilidade da dívida ativa.
- **RNF01 — Tecnologia e backend:** garante que o sistema seja desenvolvido em Python, conforme a tecnologia definida pelo projeto.
- **RNF02 — Portabilidade e dependências:** garante a reprodução do ambiente por meio do arquivo `requirements.txt`.
- **RNF05 — Manutenibilidade e organização:** mantém código, documentação e arquivos de configuração organizados na estrutura prevista.

## Should Have — Importantes, com alta prioridade

**RF07, RF09, RNF03**

- **RF07 — Avaliação do modelo:** importante para medir o desempenho do modelo com métricas adequadas antes de sua utilização.
- **RF09 — Revisão humana:** importante para garantir que os resultados do modelo sejam analisados antes de qualquer encaminhamento administrativo.
- **RNF03 — Usabilidade:** importante para que consultas, respostas e mensagens de erro sejam compreensíveis para o usuário.

## Could Have — Desejáveis, se houver tempo hábil

**RF10, RNF04**

- **RF10 — Exibição das limitações e orientações de contestação:** agrega transparência ao uso do modelo e orienta o usuário sobre revisão e contestação dos resultados.
- **RNF04 — Desempenho:** melhora a experiência de uso ao estabelecer tempo de resposta para consultas comuns, podendo ser otimizado após a consolidação das funcionalidades essenciais.

## Won't Have — Fora do escopo desta entrega

**Nenhum dos requisitos atualmente documentados foi excluído do escopo do projeto.**

Nesta primeira iteração, os requisitos classificados como *Should Have* e *Could Have* poderão ter implementação parcial ou ser concluídos em iterações posteriores, conforme a capacidade da equipe. A categoria *Won't Have* permanece sem requisitos nesta Sprint porque todos os requisitos RF01–RF10 e RNF01–RNF05 fazem parte do escopo planejado do sistema.
